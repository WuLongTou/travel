# 宇宙大爆炸模拟 · 架构与迭代说明

## 0. 需求与设计目标

1. **真实的大爆炸开场**
   - 奇点爆发、超光速式暴胀、高速喷流、冲击波和火球都要可见。
   - 暴胀后奇点附近必须空旷；原子、宇宙网、天体都在远方逐步出现。

2. **小球是自由物理体**
   - 没有预定航线，不锁定目标。
   - 只受初始动量、引力、惯性和气体阻尼影响。
   - 轨迹必须是平滑弧线，不能出现锐角折返或瞬移式转弯。

3. **宇宙稀疏，结构不能扎堆**
   - 初始位置附近不能有恒星、星团、星系、黑洞。
   - 同一时间只允许一个系统进入形成阶段。
   - 天体只能在小球航行途中缓慢、随机地遇到，不能几秒内一起冒出来。

4. **多天体集合不是单个天体**
   - 星系 / 星团 / 超星系团本身是集合：远景就要看到它是"一群天体"，
     而不是"一个渲染成星系的单个天体"。
   - 靠近时成员**逐个**真实化：先看清边缘的成员，随着行进发现越来越多，
     而不是一进来就展开整个星系。
   - 远离后真实天体卸载，退回远景成员点云，性能和内存可控。

5. **无限运行**
   - 模拟没有终点。
   - 小球被捕获且无法逃逸时，在捕获系统边缘重生并继续航行。
   - 航行过程中会定期在小球前方动态补充随机类型的休眠暗物质晕，
     让航线永远有新结构可探索。

6. **可持续迭代**
   - 架构和参数必须写入文档，方便继续扩展 N-body、行星二级系统、
     碰撞吸积、性能预算等功能。

## 1. 核心原则

- 宇宙可以无限运行，没有固定终点。
- 星空背景不是有限球壳/椭球，而是跟随相机的无限天球；
  小球无论飞多远，周围始终有宇宙星空，不会“跑出宇宙”。
- 暴胀阶段会把物质瞬间推到远方；之后才依次形成原子、宇宙网、
  恒星、星系和黑洞。奇点附近不会直接长出大质量天体。
- 小球没有预定航线。它只携带大爆炸赋予的初始动量，之后完全由
  `引力 + 惯性 + 星际气体阻尼` 驱动。
- **大型多天体系统（星团 / 星系 / 超星系团 / 黑洞系统）是集合，不是一个天体**：
  - 远景：直接把它的全部成员画成一团点云（§5.2）——看到的就是"一群天体"，
    而不是"一个渲染成星系的单个天体"；
  - 小球靠近：成员被**逐个**升级为真实天体（有引力、可碰撞、能长出二级系统），
    先看清边缘的，越往里走看清的越多；
  - 小球远离：真实天体卸载，退回远景成员点云，性能和内存可控。
- 小球落入天体核心或黑洞事件视界后，判定为“完全无法逃逸”，
  在捕获它的系统边缘生成下一代小球继续航行。

## 2. 模块划分

按域拆分（2026-08-30 目录梳理最终态，迁移节奏见 §"目录梳理"）：

```
src/
  cosmos.js          # 聚合入口（仅 33 行，re-export 物理/渲染域，外部 import 路径不变）
  core/
    config.js        # 顶层常量与默认配置（~35 个纯数据）
    utils.js         # 跨域共用的纯工具（randomUnit/clamp01/smoothstep/orbitPolar/hash01 等）
    sim.js           # 物理域：CosmicSimulation / levelForSeed / LEVEL_LABELS
  render/
    renderer.js      # 渲染域：createCosmosRenderer + 全部渲染辅助
                     #   （纹理/颜色/天空/星场/爆炸特效/镜头）
  main.js            # 入口：组装各域、启动主循环、绑定控制面板与 HUD
  audio.js           # 音频分析与示例音乐
scripts/
  smoke-discovery.mjs  # 无头冒烟脚本，量化「渐进发现」的节奏（见 §5.2 ⑤）
docs/
  SIMULATION.md        # 本文档：单一真源，后续迭代先更新这里
```

**域边界**：物理域（`core/sim.js`）只关心"宇宙演化物理"——不引入 Three.js 或 WebGL；
渲染域（`render/renderer.js`）只关心"把 sim 的状态画出来"——通过参数拿 sim 对象，
不引用 `CosmicSimulation` class 本身。共用工具与常量抽到 `core/utils.js` /
`core/config.js`。`cosmos.js` 作为聚合入口 re-export，外部
（`main.js` / `smoke-discovery.mjs`）的导入路径完全不变。

## 3. 大尺度宇宙演化

- 约 57 个暗物质晕，分为四档：
  - `small` → 行星
  - `medium` → 恒星 / 星团
  - `large` → 星系 / 超星系团
  - `giant` → 极少数坍缩为超大质量黑洞，其余停留在**巨椭圆星系**
- 按径向分带分布，覆盖从近到远的漫长航线：
  - 小质量晕：约 `180 ~ 1980`
  - 中等质量晕：约 `380 ~ 3330`
  - 大质量晕：约 `650 ~ 4700`
  - 巨质量晕：约 `1000 ~ 5500`
  奇点附近是空的，不会凭空出现恒星/星团/星系/黑洞。
- **黑洞的稀疏性（符合真实宇宙）**：`giant` 数量由 8 降至 **3**，
  且只有约 35% 的 `giant` 种子的 `willCollapse` 标志为真（确定性
  hash01 决定）才会最终演化为黑洞；其余停留在巨星系阶段。
  实测平均每个宇宙约 **1 个黑洞**（在 57 个天体中 ≈ 1.8%），
  符合"活跃黑洞（吸积盘点亮）在真实宇宙中极罕见"的分布。
- 600 个普通物质粒子是远方暗物质晕周围的原初气体云，
  220 个粒子表现为从奇点喷出的高速可见喷流（**EJECTA_SPEED 160~320，
  爆炸窗口内 1.4/s 乘性减速——超光速扩张后逐渐放缓**，避免喷飞太远
  破坏结构形成）。
- **结构不是按时间表统一生成的**：
  - 只有小球靠近某个晕到 `SEED_AWAKEN_RADIUS`（220）内，该晕才会被唤醒；
  - 同时最多允许 3 个系统并行形成（`FORMATION_SPACING = 1.5s`），
    并且**总是唤醒离小球最近的种子**——小球飞行速度（上限 34）快于形成
    速度，若一次只允许一个系统形成，多数种子会在门控期间被甩在身后；
  - 小球靠近（150 单位内）时形成速度最高加速 2.5 倍，保证小球很早就
    “看见”结构成形，而不是贴近时才突然生成。
- 形成过程持续 3~7.5 秒（小质量行星最快，巨质量黑洞最慢），所以行星、
  恒星、星系、黑洞都是沿途提前、平滑地出现，而不是几秒内一起冒出来。
- 部分暗物质晕会沿小球初始喷射方向形成“宇宙纤维结构”，
  这只是初始条件分布，不是航线；相遇与否由后续物理决定。
- 同时，系统会定期（每 5.5 秒）回收远处仍休眠的旧暗物质晕，按质量函数
  偏中 / 大 / 巨 重新设置为新的天体系统，并投放到小球前方 300~560 单位
  远处（散乱角 0.28；约为星系直径的 2.3~4.3 倍——尊重"星系际空间
  极其空旷"的宇宙常识）。每次只生成一个，**靠其巨大引力范围把小球慢慢
  拉过去**，而不是贴脸生成；这模拟了"宇宙很空，天体距离很远，
  但引力范围很大"的真实宇宙观。
- 新投放的种子即使还未演化，也会以发光的暗物质晕光点显示（休眠点也清晰可见），
  并拥有真实质量；小球靠近时会被其引力偏转，靠近到唤醒半径后开始形成结构。
- 引力影响范围随形成进度扩张：
  `influenceRadius = 4.5 + growth * (12 + mass * 6) + mass * 1.4`，
  对巨质量黑洞可达数十单位以上，使小球在很远就能"看见"并被偏转。
  **黑洞（超大质量）额外 ×1.6**——真实 SMBH 引力井极深、影响光年尺度。
- 为了能让“引力拉扯”被明显感知，小球自身的引力计算使用
  `PROBE_GRAVITY_MULT = 2.0`，只增强小球感受到的天体引力，
  不影响物质粒子演化。
- 小球速度有上限 `PROBE_MAX_SPEED = 34`：引力弹弓加速有界，
  保证“航行节奏 / 形成节奏 / 跟拍节奏”三者始终匹配。

### 3.1 性能预算与自适应降级

细节生成受两级可配置预算约束（`sim.config`，控制面板滑杆直通）：

- **细节系统上限** `maxDetailSystems`（默认 3，滑杆 1~6）：同时持有
  内部细节的系统数；超限时未生成的系统保持远景表示，并提示一次
  `⚙️ 已达细节预算上限`（每系统只提示一次）；
- **细节体上限** `maxDetailBodies`（默认 1000，滑杆 100~1500）：全部活跃
  系统的细节天体总数（一个星系约 300~400 成员 + 超星系团 ~220 成员 + ~210
  子星系恒星，上限随之调高）。

FPS 自适应降级（"⚙ 自动降级"开关，默认开；`config.qualityTier` 0/1/2）：

- EMA 帧率 < 40 FPS（每 5 秒评估）→ 升一档，事件提示当前档位；
- EMA 帧率 > 45 FPS 持续 10 秒 → 逐档恢复（40~45 为稳持带），避免来回跳；
- 档位 1：冻结 LOD 升级、停止创建新细节系统（存量保留）；
- 档位 2：把最远的细节系统卸载到上限一半、细节点尺寸 ×0.8；
- 降级时新创建的成员布局也按档位缩减数量（×0.75 / ×0.55）；
- 关闭开关立即恢复档位 0（全质量）；HUD"宇宙"行显示当前档位（降级N）。

### 3.2 初始条件参数化

三个初始条件暴露为滑杆（`sim.config`，"🎲 重开宇宙"后生效，
localStorage 持久化、刷新后保留）：

- **纤维凝聚** `filamentStrength`（0~2，默认 1）：整体缩放暗物质晕
  贴附小球航向的概率——0 = 完全均匀各向同性宇宙，2 = 强纤维结构；
- **速度弥散** `velocityDispersion`（0.3~2，默认 1）：物质初速随机
  散布倍率（保持平均速度不变）——0.3 = 整齐的膨胀流，2 = 剧烈湍流；
- **质量偏置** `massBias`（-1~+1，默认 0）：在质量函数两端搬运数量
  份额——负值偏小质量（行星/恒星更多），正值偏大质量（星系/黑洞更多），
  中档数量不变，每档最少保留 2 个。

`CosmicSimulation` 构造函数接受 `initialConfig` 注入初始条件；
运行时滑杆只改 `config`，点"🎲 重开宇宙"（reload）后生效。

## 4. 小球的自由物理

- 初始状态：暴胀结束后从奇点附近出发，只携带惯性速度
  `PROBE_INITIAL_SPEED ≈ 24`，方向随机。
- 每个模拟步：
  1. 计算所有暗物质晕的引力，记录对小球施加强引力、需要镜头聚焦的系统。
     质点质量按系统类型区分（修正过的建模）：
     - **单天体系统（星尘/行星/恒星）**：种子就是天体本身，质点**永不退场**
       ——飞向恒星时它的引力全程存在（此前按 detailRadius 退场导致贴身
       引力归零，只剩质量极小的行星成员，观感即"引力算错了"）；
     - **集合系统**：远场由质点承担（多极展开单极项），进入系统后退到
       **0.45×mass 的底数**——已发现的成员只是一小部分，几百个质点也
       代表不了 10^11 恒星 + 暗物质晕的连续引力场，星系内部的引力不该
       凭空消失。总有效质量始终 ≤ s.mass，与成员引力不重复计入。
  2. 计算当前已生成细节天体（恒星/行星/黑洞等）的引力。
  3. 进入系统内部后施加**按层级 + 深度线性**的星际气体阻尼（**速度-尺度
     协调**，2026-08-30 重做）：原实现范围只到 `systemRadius`（恒星系
     仅 3.4、行星系 1.7），小球 30/s 巡航穿过恒星系只花 0.9s、行星系
     0.3s，伴星/行星/小行星带根本来不及看清（实测小球速度是成员轨道
     速度的 17~60 倍）。现在：范围扩到 `max(systemR, detailR*0.75)`，
     强度按层级分档（小系统强、大系统弱，避免宏观被吸太黏）：
     - 行星/恒星/星尘 2.2/s —— 贴近核心时降到 5~10/s，能看清伴星/行星
     - 星团/黑洞 0.9/s + 黑洞内圈 +0.8
     - 星系/超星系团 0.45/s —— 高速穿越，核区自然减速观察
     实测：恒星系（dr=14）核心 ~6/s 环绕，星系（dr=115）前 5s 保持
     25+ 穿越、5~7s 减速到 17~11 进入核区（不再被吸在距 65 死黏）。
  4. 巡航恢复：被系统阻尼减速后，离开系统（drag=0）且速度 < 24 时
     0.1/s 向 `PROBE_INITIAL_SPEED` 松弛——避免"8/s 爬行 50s"的无
     聊空旷航段（游戏化的巡航引擎维持，不影响捕获判定）。
  5. 子步长积分 `dt <= 0.008`，保证近距离强引力下稳定。
  6. 检测是否撞入天体核心 / 事件视界；速度超过 `PROBE_MAX_SPEED` 时截断。
- 重生：速度 `PROBE_RESPAWN_SPEED ≈ 30`，在系统边缘（`系统半径 × 1.1`）之外
  重生，并给予 6 秒捕获宽限期——足够逃出大系统引力场继续航行；
  重生/虫洞的大尺度瞬移由镜头做**刚体平移**跟随（见 §8.1），朝向不变。
- 渲染层还会对小球显示位置做一阶平滑插值，消除固定物理步长造成的微抖动。
- 渲染循环由 `requestAnimationFrame` 驱动，与显示器刷新同步；物理步长
  （50Hz）与显示帧率（60Hz）不同步时，渲染层在相邻两个物理步之间按剩余
  相位插值出显示位置，保证小球运动平滑连续（个别不派发 rAF 帧的 headless
  环境会看门狗式退回 setInterval 驱动）。
- 没有任何 `target`、`visit` 或顺序表。小球可能掠过、被偏转、
  暂时绕行、被捕获，也可能直接飞走。

### 4.3 天体间万有引力（N-body，2026-08-30 新增）

种子（天体系统）之间原本完全无引力（只惯性 + 微阻尼），彼此独立、
互不影响，违背万有引力常识。新增**种子间 N-body 软化引力**：

- 每对种子按 `a = seedGravity × m_other / r²` 互相吸引（方向指向对方），
  每物理步 O(n²) 全连接（n≈57，3249 对）积分到 `s.vel`——廉价；
- 软化 `SOFT = 50²`：种子半径 30~50，近距离不产生奇点；
  速度有界 90/s，极端情况不失控；
- 强度 `config.seedGravity`（默认 **400**，滑杆 0~4000）：默认值下
  r>200 的加速度 <0.01/s²，远场仍以 Hubble 流（30~55/s）为主、不会
  全局坍缩；近距离（<100 单位）大系统才开始互相可感知地偏转；
  调大（2000+）可观察到两个星系明显的相对接近与绕行；
- 与现有机制共存：超星系团内核的分析轨道绕行保持不变，新增的是
  seed 与 seed 之间的**平动引力**（整体位移互相吸引）。
- 实测：两种子（质量 0.22/0.15，间距 80，seedGravity=4000）10s 内
  从 80 靠近到 75.7 并持续加速——万有引力互相吸引生效。
- 验证：smoke 3 次随机宇宙相遇率正常（run 2/3 深入 42-50%），引力
  未破坏"渐进发现"节奏。

## 5. 按需生成的大规模多星体系统

触发条件：`小球到某个大系统的距离 < detailRadius * 1.4`（提前生成）。
卸载条件：`小球到该系统的距离 > detailRadius * 2.4`。
近距离动态加载，远距离立即卸载——性能和内存可控。

### 5.1 二级系统：靠近恒星时显现它的行星（§9.2/9.8）

集合系统（星团 / 星系 / 超星系团 / 黑洞系统）内部的恒星只有光点；
当小球贴近其中某颗恒星（距离 < `max(2.0, 恒星半径 × 55)`）时，
为该恒星即时生成 2~4 颗行星/气态巨星（`_generateStarChildren`）：

- 子天体绕**恒星本身**运动（母星是移动目标，每步用其新位置积分）；
- 对小球产生真实引力，撞上即被捕获（行星/卫星 = 大气烧蚀）；
- 渲染上追加到系统点云的预留槽位（容量 +220），显示位置 =
  母星插值位置 + 自身轨道角插值，与系统整体同步平滑；
- 较大的二级行星可带**粒子环**（土星式，见 §5.4）；
- 子系统一旦生成就保留到系统卸载（再次靠近无需重建，有连续感）；
- 降级档位 ≥1 时不再生成新的二级系统；首次生成提示一次
  `🪐 小球贴近一颗恒星，它的行星系统在眼前显现`。

### 5.2 渐进发现：成员逐个真实化

**不再使用"到达某个距离整层展开"的 LOD**——那样一靠近就看到整个星系，
与"星系是多天体集合"的直觉相悖。现在分三层表达：

#### ① 确定性成员布局（`_memberLayout`）

一个系统的全部成员（类型 / 质量 / 轨道半径 / 高度 / 角速度 / 起始相位 /
离心率 / 近点角）由 `seed.idx` 确定性地生成一次并缓存，**与小球的位置无关**。
远景点云与真实 detail 天体共用这一份布局，接管时位置天然连续。

`layout[i].tier` = 结构层（0 外圈 / 1 中圈 / 2 内圈），只影响远景点云的
尺寸与亮度层次；决定"谁被看清"的永远是小球的行进，不是 tier。

布局的自转相位统一为 `angle = 布局起始角 + seed._layoutSpin × 角速度`。
`_layoutSpin` 每步随模拟时间推进，因此远景点云与 detail 成员即使在不同
时刻创建，也永远落在同一相位上，交接瞬间不跳变。

**椭圆轨道（开普勒）**：轨道角统一存"平近点角"M（随时间线性推进，与上面
的 spin 公式严格一致）；`e > 0` 的成员经开普勒方程 `M = E - e·sinE`
（牛顿迭代 4 次）解出真近点角，半径 `r = a(1-e²)/(1+e·cosν)`——
近快远慢（第二定律），轨迹是椭圆。`e = 0` 退化为旧的匀速圆轨道，
渲染插值对 M 线性插值后代入公式，天然连续（`orbitPolar`，全局唯一实现，
物理侧 / 预览点云 / 细节点云三处共用）。

#### ② 远景成员点云（渲染层 `updatePreviewClouds`）—— 三段式层级

集合系统的表达遵循真实的"层级连续体"（用户明确要求）：

| 相机距离 | 表达 | 说明 |
|---|---|---|
| 远（> ~4.5×detailR） | **只有 halo/core 光斑** | 极远处分辨不出旋臂与星点——星系就是"一个"天体（一团光），成员点云整体淡出 |
| 中（1.4× ~ 4.5×detailR） | **成员点云** | 光斑随小球接近退场，恒星星群浮现——看到的是"一群恒星"，"星系"整体已不可见；点云带最小像素钳制与 `uBoost` 远距补偿（只服务本段） |
| 近（< 1.4×detailR） | **身边的天体** | 只剩单个天体，航线经过谁、谁才显形（③逐个发现） |

- 成形前与远距的"单个发光天体"表达由 halo/core 承担；实心球随 `growth`
  0.6→0.85 完全退出，核球辉光随小球进入（0.7R→1.15R）彻底退场——
  深入星系后中心不再挂任何"整体光球"；
- 圆环盘面贴图彻底退场（星系轮廓完全由成员粒子构成）；
- 点云淡入区间 `growth` 0.5→0.7 × 距离淡出 `1-smoothstep(3.2R, 4.5R, cd)`，
  与光斑退场区间重叠，中间没有空窗。

#### ③ 逐个发现（`_revealMembers`）

小球进入 `detailRadius * 1.4` 后系统创建真实 detail 天体，但**初始全部
未发现**（隐藏、无引力、不可捕获）。每个物理步（50Hz）里：

- 找出与小球距离小于 `REVEAL_RADIUS[type]` 的未发现成员——
  黑洞 24 / 星系核 20 / 恒星 10 / 行星 5 / 气体 4 / 小行星 3，
  再按系统尺度平方根放大（`REVEAL_SCALE = 0.6+0.9√(detailR/30)`，
  星系 ≈2.36、超星系团 ≈2.24、星团 ≈1.5；线性外推会让大星系的
  恒星在 40 单位外就被"看清"，稀疏感荡然无存）。
  阈值取**绝对世界距离**：
  "看清一颗恒星"不随宿主系统的尺度变化，所以星系再大也不会一进来就全开；
- 按距离升序，**每步最多揭示 `DISCOVERY_PER_STEP = 2` 个**，防止高速穿越时
  一帧全开。

于是观感是：**掠过系统时只看见满天远景光点；越往里走，越靠边的成员先
变成真实天体，并由外圈向内圈逐步推进**。发现是不可逆的（同一趟里持续
可见、有引力、可碰撞、能长出二级系统），但小球远离到 `2.4R` 之外时
detail 卸载，重新靠近会从远景点云再次开始发现。

#### ④ 交接：同位置、逐成员

未发现的成员由预览点云画在**真实轨道位置**上；被发现后预览点随 `revealT`
淡出，真实点云在**同一位置**原地淡入（尺寸 25%→100%、亮度 0→1）。
所以是"从模糊光点聚焦成真实天体"，不是"凭空出现"，也不会出现重影。

#### ⑤ 怎么验证节奏（`pnpm smoke`）

发现的节奏是纯手感问题，肉眼很难判断对不对，所以用无头脚本量化：

```
pnpm smoke            # 默认 600s
pnpm smoke 90         # 指定模拟秒数
```

它会按「小球**最近**接近深度 ×R」把遇到过的系统分桶，报出各桶的平均发现率
与"一个都没发现"的系统数，并对进入最深的系统给出「首个发现 → 90%」的耗时
与采样轨迹。

判据（新尺度实测基线，2026-08 尺度真实化改造后）：

| 最近接近深度 | 期望发现率 |
|---|---|
| 深入腹地 `<0.5R` | ~10%（穿越路径沿途的恒星逐一显形，几十颗） |
| 只到边缘 `0.8~1.1R` | 个位数，多数为 0（在成员云之外） |
| 擦过 `>1.1R` | 0% |

星系成员稀疏是刻意设计（星际距离）：绝大多数成员保持远景光点，
只有航线直接经过的恒星才升级为真实天体。旧基线（密集布局下
`<0.5R ≈ 99%`）已随尺度真实化废弃。

改 `REVEAL_RADIUS` / `DISCOVERY_PER_STEP` 后重跑，对照这张表看节奏是否漂移。
注意 600s 约需 2 分钟墙钟，嫌慢就调小秒数。

### 5.3 集合系统动力学：恒星间相互引力微扰（§9.7）

分析轨道提供形态基线，恒星（mass ≥ 0.01）之间以软化引力互算
（`DYN_G`，20Hz 重算 O(n²)，仅恒星参与）产生有界速度漂移 `bv`
（封顶 0.8、阻尼 e^(-0.35t)），以偏移 `boff` 叠加在轨道位置上。
相对运动是真实的 N-body 力（星团互绕、旋臂扰动），但构造上
不可能逃逸或瓦解。降级档位 ≥1 或 `config.systemDynamics = false`
时整体关闭，回到纯分析轨道。

### 5.4 各类系统的细节生成规则与尺度阶梯

**尺度阶梯（`_detailRadius`，尊重宇宙尺度常识）**：

| 系统 | detailR | 特征 |
|---|---|---|
| 行星系 | 5 | 卫星贴身 |
| 恒星系 | 14 | 行星轨道铺开到 ~10 |
| 星云 | 26 | 弥散气体云 |
| 星团 | 30 | 球状星团，恒星相对密集（真实如此） |
| 黑洞系统 | 36 | 核球恒星紧密绕行 |
| 超星系团 | 100 | 星系核隔着几十单位的"星系际距离"相互绕行 |
| 星系 | 115 | 直径 130+，穿越约 80 屏幕秒；盘面恒星间距 ~2.8（恒星物理半径 ~0.05，即 50+ 倍间距）|

系统类型与成员规则：

- 星云 / 尘埃云：90~150 个气体尘埃粒子 + 少量亮星。
- 恒星系统（真实化改造）：
  - **单星 / 双星 / 三星**：约 55% / 35% / 10%——伴星是绕主星（种子本体）
    的成员天体，靠近才被发现；行星全部排在伴星轨道外侧 >2.2× 分离距
    处绕系统公转（环双星轨道）；
  - 行星轨道带离心率（e 0~0.16）；
  - **小行星带**：70~110 个微小暗成员分布在两条行星轨道之间；
  - **彗星**：1~2 颗高离心率（e 0.45~0.65）气体成员，近日疾驰、远日缓行；
  - 较大的行星可带**粒子环**（30~58 粒，土星式；复用 children 机制，
    标记 `deco` 纯装饰无碰撞，随母行星 revealT 淡入）。
- 行星：0~3 颗小卫星，点缀在行星周围。
- 星团：30~45 颗（结构层 0）+ 45~70 颗（结构层 1）颗真实恒星，三维球状分布。
- 星系（真实结构分层，约 300~400 个成员，取代"盘面贴图 + 光晕底雾"）：
  - 形态由 seed 确定性派生：**旋涡 ~55% / 棒旋 ~25% / 椭圆 ~20%**；
  - 旋涡/棒旋 = 核球+中央棒（密集的老年暖星——星系里唯一密集的区域）
    + 2~3 条**对数螺旋臂**（`r = rMin·e^(pitch·θ)`，臂上稀疏的蓝白年轻星
    + 气体云撑起臂的可读性）+ 刻意稀疏的盘面场星 + 稀疏银晕；
  - 椭圆 = `r^2.2` 向心集中的三维球状分布、老年暖星、约 25% 逆行轨道；
  - **恒星颜色按光温分布**：蓝白（年轻）→ 黄白 → 橙红（老年），
    远景点云与近景点云同一套三段配色；
  - **较差自转**：角速度 `ω ∝ r^-0.85`（近似平坦旋转曲线）——内侧略快
    外侧略慢，有真实星系的剪切感，又不会把旋臂快速缠死。
- 超星系团：6 个星系核在 10~55 单位的轨道上相互绕行（星系际距离）。
  **每个星系核展开成"子星系"（children）**——核球 4~6 颗老年暖星 +
  双对数螺旋旋臂 14~18 颗（含 ~30% 气体云撑轮廓）+ 场星 6~9 +
  星际尘埃云 6~9，共约 30~42 颗/核，较差自转 `ω ∝ r^-0.85`；
  另每核带 24 颗外层恒星云 + 10~16 星际尘埃（远景成员点云可读）。
  **超星系团里的"星系"不再是整体光点**：靠近某个星系核时看到的是
  一个有旋涡、有自转、有尘埃的真星系。
- 黑洞系统：**1 颗中心黑洞（事件视界）** + 16~24（层 0）+ 30~44（层 1）
  + 18~28（层 2）颗核球恒星/行星。中心黑洞是致密引力源，小球进入事件
  视界即触发潮汐撕碎（`tidal` 死亡），是"黑洞捕获"的物理实现。

这些细节天体：

- 使用较大的点尺寸 + 尺寸随距离衰减的 shader，即使在一定距离外也清晰可见
  （不再是亚像素光点，肉眼即可分辨出一片恒星/行星）；
- 持续绕中心运动；渲染时对轨道角做帧间插值，绕行天体同样平滑无抖动；
- 对小球产生真实引力；
- 与小球发生碰撞捕获；
- 在 `activeDetails` 中注册，供渲染器同步生成点云；
- 小球远离后从 `activeDetails` 移除并释放对应渲染资源。

## 6. 重生与虫洞跃迁

### 6.1 普通重生

触发条件：

- 小球撞上"单天体"（星云 / 行星 / 恒星）核心；
- 或小球撞上细节天体（恒星/行星/黑洞等集合中的成员）。

行为：

- `generation += 1`；
- 在捕获系统的边缘重新生成小球，速度沿径向 + 随机切向；
- 旧轨迹清空，播放重生冲击波；
- 事件提示第几代小球继续航行。

**差异化死亡方式**：捕获先进入**死亡序列**（`_beginDeath` → `_updateDeath`），
播完演出才重生——物理冻结（`pr.dying`），朝杀手天体缓慢下沉
（潮汐型叠加切向螺旋），序列时长按死法区分
（汽化 0.7s / 烧蚀 1.1s / 潮汐 1.3s）；结束时走原重生逻辑
（含持续捕获的虫洞检测）。渲染层演出：

- `atmosphere` 坠入行星/星尘大气：🔥 小球缓慢压缩、暖橙单环慢扩散；
- `vaporize` 被恒星吞没：☀️ 小球收缩蒸发、白炽强闪快扩散；
- `tidal` 靠近黑洞/星系核：🕳️ 小球沿杀手方向意大利面化拉伸
  （1+3.5k, 1-0.8k, 1-0.8k）+ 蓝白三重延迟涟漪（撕碎回声）；
- `wormhole` 虫洞逃逸不播死亡特效（全屏虫洞叠加层已足够）。

死亡点与重生点分离：特效在死亡序列起点播于 `deathPos`（被捕获处，
重生时去重不重复播放），重生冲击波仍在重生边缘，
小球光晕颜色在死亡与重生高亮期间都跟随死法。

### 6.2 星系 / 星团 / 黑洞 不会被整体捕获

**关键设计**：星团 / 星系 / 超星系团 / 黑洞 本身是"集合"，不作为整体捕获小球。
小球只会被这些集合内部的某个成员（具体某颗恒星/行星/黑洞）捕获，
因此可以自由穿越星系、掠过星团核心、从黑洞旁擦过——前提是没有撞上具体成员。
这避免了"小球进入星系就被弹出来"的粗糙感。

`_captureRadius(s)` 只对 `star` / `planet` / `dust` 返回非零值；
`cluster` / `galaxy` / `supercluster` / `blackhole` 返回 0（集合不整体捕获）。

### 6.3 虫洞跃迁逃逸

如果小球**短时间内反复被同一系统的成员捕获重生**（普通重生治标不治本），
普通重生机制会失效。检测到这种持续捕获时（同一 `seed.idx` 在
`WORMHOLE_RECAPTURE_WINDOW = 8` 秒内反复触发），不再重生到系统边缘，
而是触发**虫洞跃迁**：

- 在小球当前位置播放全屏虫洞特效（旋转能量环 → 白闪 → 蓝色过曝）；
- 把小球瞬移到**安全目标点**（见 6.4 的安全重算）——不再是固定距离
  的盲目跳跃，确保落点距任何天体 ≥ 安全余量，真正脱离捕获范围；
- 给予新航向 + `PROBE_RESPAWN_SPEED` 初速度；
- 重置捕获记忆（`lastCaptureSeed = -1`）；
- `generation` 不变（虫洞是逃逸不是死亡）；
- 事件提示 `🌀 小球被【...】持续捕获，经虫洞跃迁 X 单位（距最近天体 Y）真正逃逸`。

虫洞特效是一个全屏 shader 叠加层，持续 `config.wormholeDuration` 秒。

### 6.4 虫洞可配置性

四个参数已实例化为 `sim.config` 并暴露为控制面板滑杆，实时生效：

- **虫洞距离** `wormholeDist`（默认 800，滑杆 300~4000）：跃迁落点的基础距离；
- **跃迁安全余量** `wormholeSafeMargin`（默认 200，滑杆 100~600）：跃迁落点
  距任何天体的最小距离。**安全重算**（2026-08-30 新增，解决"瞬移后依然
  被捕获"循环）：`_wormholeEscape` 采样最多 8 个候选方向（含速度反方向），
  对每个方向评估"跳 wormholeDist 后距最近天体的距离"，优先选满足安全
  余量的方向；都不满足则沿当前最空旷方向把距离翻倍重试（×1~×4），
  直到安全或到达上限。实测 57 个种子旁触发虫洞全部满足安全余量；
- **虫洞动画** `wormholeDuration`（默认 1.4s，滑杆 0.6~3s）：全屏动画时长，
  渲染层按 `pr.wormholeDuration` 计算进度，滑杆改变只影响之后触发的跃迁；
- **持续捕获窗口** `wormholeWindow`（默认 8s，滑杆 2~20s）：窗口内被同一
  系统再次捕获即触发虫洞；调小更难触发（更多次普通重生），调大更易逃逸。

## 7. 远景 / 近景渲染

- 星空背景：使用跟随相机的单位天球 Shader 背景 + 环绕相机星点，
  不是有限的宇宙边界。
- **星场（真实感重做，2026-08 全面整改）**：三层亮度的真实星等幂律分布
  （暗 7000 + 中 900 + 亮 130），颜色按黑体色温从蓝白(O/B)到橙红(M)
  连续采样，配合 UnrealBloom 后处理呈现"亮星发光"质感。
- **远星云层（增强多样性）**：18 团巨大、极淡的彩色气体云，调色板扩到
  12 色（深蓝/青/品红/暖橙/翠绿/紫罗兰等），每团长宽比随机（0.35~1.2）
  ——有的细长如纤维、有的浑圆如泡，旋转角也随机。跟随相机，给"真实
  宇宙"补上色深与形态多样性。Additive 混合 + depthTest off。
- **远景天体的色调多样性**：每个 seed 在创建时按 `seed.idx` 确定性生成
  一组 HSL 偏移（hue ±0.07, sat ±0.08, lightness ±0.05），应用到该
  seedGroup 的 solid/core/halo/disk 配色。同一类型（galaxy/cluster/...）
  的不同天体颜色各异——有的偏蓝、有的偏紫、有的偏青，体现宇宙多样性。
  黑洞吸积盘的暖橙基调在 tint 后保持暖色域，不破坏辨识度。
- **后处理辉光 UnrealBloom**：通过 EffectComposer + RenderPass +
  UnrealBloomPass（strength 0.85 / radius 0.55 / threshold 0.30），让恒星、
  小球、轨迹、星云都带上真实发光感。**按性能档位门控**：
  `bloomPass.enabled = (sim.config.qualityTier === 0)`，降级档位 ≥1 时
  关闭以保帧率。
- 主角小球（**游戏风格能量球**，2026-08 重设计）：`ShaderMaterial`
  能量球（半径 0.5）——亮白核心 + 青蓝菲涅尔边缘 + 顶部镜面高光
  （固定光源 `L = (0.35,1.0,0.6)`, `pow(dot(R,v), 42)`），配合
  corona（半径 0.85 青蓝菲涅尔）+ glow/halo 青蓝双层光晕，bloom 后
  呈现清晰的"能量核心"游戏感。
- **运动轨迹（恒定宽度缎带）**：相机朝向的三角带(ribbon)，
  **头部与尾部同宽**（`w = TRAIL_HALF_WIDTH` 恒定 0.26）——
  近端不加粗，消散只靠 alpha 按 `t^1.5` 衰减到零。additive + bloom
  呈等宽发光带。缎带每帧依据当前相机位置重建
  （side = 视线 × 切线），始终正对相机。
- 远景：休眠/形成中的暗物质晕使用 sprite 光晕、环盘等低成本对象;
  成形后按 §5.2② 的三段式表达（远=一个光斑 → 中=成员星群 → 近=单天体）。
- 近景：`updateDetailVisuals()` 为每个已生成细节的系统创建独立
  `THREE.Points` 点云，写入**已发现**成员的位置、颜色与大小;
  未发现的成员继续由远景成员点云表达，两者同位置、按 `revealT` 交叉淡变。
- 恒星颜色按光温三段分布（蓝白/黄白/橙红），远景与近景同一套配色。
- **黑洞（真实引力透镜 + 吸积盘，无夸张光晕）**：
  - 事件视界：纯黑球（`MeshBasicMaterial` RGB 0,0,0），**无任何 halo/glow
    光晕**——黑洞本身是黑的，不发光。
  - **光子环（爱因斯坦环）**：紧贴视界外侧（~1.5×视界半径）一圈极细
    亮白环（`TorusGeometry(1.5, 0.022)`），是引力透镜把背景光弯成
    的标志视觉。
  - **吸积盘（shader）**：扁平的等离子体盘（`RingGeometry(2.0, 6.0)`），
    自定义 GLSL Shader：内缘白热、外缘红橙（真实温度梯度），
    多普勒增亮（盘旋转，`sin(ang)` 一侧更亮），additive 混合；
    随黑洞自转旋转（`diskAngle × 0.55`）。
  - **相对论喷流（自然消散）**：粒子流沿自转轴两极（`jetA/jetB`），
    56 粒/极；**长度有限**（`z ∈ [0.5, 2.7]`），亮度按 `(1-t)^1.6`
    衰减到零——喷流在远端自然消散，不是无限延伸的实心光锥。
- 细节系统卸载时，同步 dispose geometry/material。

## 8. 交互与视角操作

**只有一台自动镜头：轨迹优先的连续上帝视角。** 没有镜头模式机、没有
滞回锁存、没有 AABB 自动框选——所有控制量都是连续函数，结构上不存在
"模式切换瞬跳"。镜头永远不跟着小球的速度方向旋转，也不会因为接近某个
系统而突然拉近/换视点。

### 8.1 连续上帝视角

- **方位角恒定**（初始化定一次，之后不动）+ 极缓慢正弦漂移
  （±1.7° / 周期约 5 分钟）；**俯角固定 ≈34°**（同样带 ±0.7° 微漂移）；
  无滚转（up 恒为 +Y）。任何绕行、引力弹弓都不会引起镜头旋转或翻转；
- **相机位置 ≡ 视点 + 球坐标偏移**，与视点距离恒为当前 `camDist`：
  结构上不可能贴脸、不可能翻面。**默认巡航距离 55**（拉远——不盯小球，
  让宇宙与轨迹全貌入画），基础 FOV 58°，并叠加**随速度的 FOV 拉伸**：
  `targetFov = 58 + min(16, speed·0.5) + beat·1.5`，制造"冲刺"张力。
  退出跟拍（自由观察）时 fov 收回 58，由 OrbitControls 滚轮控制远近；
- **视点 = 小球 → 系统中心的连续加权 + 前向偏置**：
  - 连续上下文权重 `w` 由三个信号（切向速度占比 / 累计方向角 / 距离窗口）
    直接给出连续值，双时间常数平滑（进入 2.5s、退出 6s）——
    自由飞行时 `w≈0`，视点沿平滑速度方向前移 **1.25s 行程（上限 32% 距离）**，
    小球被推到画面后侧、轨迹在身前铺开——重点看轨迹与宇宙，不盯小球；
  - 绕行时 `w→1`，视点几乎钉在轨道中心，整条轨迹圆留在画面里；
  - 视点基准用限速平滑后的轨道中心（influencer 切换不瞬移）；
- **距离 = 三层取最大**，全部连续 + 速率限幅（相对变化 ≤10%/s）：
  ① 缩放滑杆基准（**默认 55**，范围 10~80）；② 绕行时按轨道半径 ×2.4 拉远（随 w 混合）；
  ③ **轨迹感知框距**——从轨迹缓冲取最近 **~44s** 的自适应窗口（慢速航行
  窗口长、纳入更多轨迹；快速航行窗口短），按包围半径 / sin(fov/2)
  拉远，`fitCap = zoomBase · 1.20`——保证"看的是航行轨迹，
  不是只盯着小球"；上限 320（星系直径 130+，绕行大轨道需要拉很远）。
  在星系内部时镜头保持局部视角——从星系内部本来就看不全整个星系，
  全貌由远景点云表达；
- **大尺度瞬移**（虫洞跃迁 / 重生）：检测到单帧位移 >100 后，把镜头与
  平滑中心**刚体平移**同样的位移量——纯平移不改变任何朝向，配合全屏
  虫洞特效，视觉上只有前景天体瞬间切换；同时清空轨迹缓冲；
- 视点再做 ≤12%/帧 的 lerp 收尾；timeScale 越高跟随越紧
  （`tsBoost = sqrt(timeScale)`）。

### 8.2 开场与大爆炸

大爆炸是"一瞬间"——所有爆炸视觉在 ~1.2s 内完成并消散，物质早已飞散。
曾用 `exp(-0.42t)` 的余晖让蓝色光晕残留 10 秒，曾用 `uAlpha=1` 持续 5 秒，
都是"小球飞走后光环还在"的问题，已全部压缩到爆炸窗口内。

- **生命周期的瞬间性**（`updateExplosion`）：
  - 白热奇点闪光：`exp(-12t)` 顶格 `0.4+flash*1.35`，~0.5s 消散
  - 中心火球：膨胀速度 `0.28 + t*4.2`，`exp(-5.5t)`，~0.9s 消散
  - 球形冲击波：~~扁平"光圈" billboard~~ → **体积冲击波球壳**（3D `SphereGeometry`
    DoubleSide + 菲涅尔，从奇点以 160/s 超光速膨胀到 ~500 单位覆盖整个
    场景，`exp(-1.6t)` 衰减）。从内部看是笼罩视野的发光罩（不再是
    扁平"贴纸环"，有真正的体积感），从外部看是边缘亮的膨胀光球——
    "冲击波扩散到全宇宙"的物理表现。约 2.5s 内扩散完成并消散，**没有
    残留**（之前的扁平光圈被用户嫌"又丑效果又不好"）
    ~2s 内扩散到 ~110 单位才淡出——"迅速扩散到全宇宙"
  - 余晖星云：`exp(-7t)` 顶格 0.20（之前 0.32，`exp(-0.42t)`），~0.5s 消散
  - 全屏 flash overlay `uAlpha`：0.5s 全强度 → 0.5~1.0s 快速淡出
    （之前 t<5s 恒 1 是残留元凶）
- **强度的强化**（`createFlashOverlay` shader）：
  - 奇点白闪 1.35 → 2.2（整屏过曝更强）
  - 冲击波环速度 2.6 → **3.2/s** + 宽度 5.0 + 衰减 1.5（扫过全屏持久可见）
  - 放射射线 16 条 → 18 条 + 强度 0.55 → 0.8（更密更强）
  - 中心余晖 0.9 → 1.1 + 衰减 2.6 → 4.5（更亮更短）
- **超光速飞散**（暴涨 + 小球 + 粒子三层）：
  - **宇宙整体暴涨**：每个 seed 初始化时存 `inflate`（径向 30-55
    单位/s），step 里位置 = `(s.vel + s.inflate × exp(-1.5·t)) × dt`——
    暴涨速度随时间指数衰减，2s 内基本归零，seeds 留下末速度漂移；
    这是"暴涨→减速→结构静止"的物理实现
  - 小球初速 `PROBE_BIGBANG_SPEED = 110`（之前 24），爆炸窗口内
    `BIG_BANG_WALL=1.2s` 豁免 `PROBE_MAX_SPEED=34` 截断，1.0/s 向巡航
    速度 24 指数松弛——"前快后慢"。窗口结束后正常限速
  - EJECTA 粒子初速 160-320，同样在窗口内 1.4/s 乘性减速
  - 粒子流线（streakLines）长度上限 3.2 → 11，暴涨期 alpha 顶格 0.85
    ——画面里"超光速流线"一眼可见
  - 实测：t=0.20s 整屏白热+18 射线+百条超光速流线；t=0.32s 冲击波环
    覆盖全屏 + HUD 速度 80.2
- **环境光恒定黑**（FPS 自适应降级 + 背景压暗）：
  - `bloomPass.enabled` 不再硬关：tier 0/1/2 → strength 0.85/0.5/0.28，
    始终启用只降强度，避免 bloom 开关造成的"忽亮忽暗"
  - `cosmicSky` 背景压暗到接近纯黑（base 0.006/0.009/0.020，银河带
    0.020/0.032/0.070），星点保持——"宇宙的天空是黑的"
- **开场镜头**：暴胀前 2.3 秒固定在奇点附近（缓慢环绕拉远 + 衰减抖动），
  看到完整的白热闪光→冲击波扩张→火球冷却→消散→粒子喷射流；之后
  切到跟拍追超光速飞出的小球（视点限速 lerp，无甩镜）；
- **开局快进**：前 15 真实秒以 0.5× 推进（显示层机制，见 §7 的物理量/显示量
  说明），让结构形成不被观赏倍率拖慢，同时小球开局不再狂飙；
- 关闭智能镜头进入自由视角：左键拖拽旋转、右键/中键平移、
  **滚轮 = 沿视线方向自由推进/后退**（第三人称游戏手感）、
  触屏单指旋转 + 双指平移。
  **无限移动（不受任何限制）**：
  - `maxDistance = Infinity` + `screenSpacePanning` + 提升的 pan/rotate
    速度（1.8× / 0.9），平移与旋转可到宇宙任意角落；
  - **滚轮不交给 OrbitControls 的原生 dolly**（`enableZoom = false`）：
    原生 dolly 是"朝 target 靠近"，target 被双击聚焦拉到小球附近后
    （`minDistance = 0.7`）滚轮就基本不动；且它不沿画面中心，无法
    "走到更前方"。自定义 wheel 监听把 camera 与 target **一起**沿
    视线方向平移 `dist × 0.0008 × deltaY`（近处精细、远处快速穿行），
    两者距离不变 → 不受 minDistance / maxDistance 限制，可一直前进到
    宇宙任何角落；手动推进会打断双击聚焦的 target 飞行；
  - 跟拍模式下滚轮不介入（`controls.enabled=false` 时跳过）。
  **双击聚焦**：双击画布把观察目标平滑飞向小球（lerp 5/s，
  飞近后停下），之后可用滚轮继续推进靠近——解决"远距离无法
  自主靠近"的痛点（仅在自由视角下生效）；
- 平移滑杆（camPanX/Y）沿屏幕方向偏移视点，偏移上限 35% 距离，
  高速时自动收回，物理上推不出画面。

## 10. 推进器（玩家主动操控）

项目定位从"被动观测引力"升级为"宇宙航行游戏"后，最核心的缺失是
玩家**没有任何输入**——小球只受引力与阻尼，不能加速、不能转向、不能
主动抵近/逃离天体。第八轮加入"可关闭的键盘推进器"，让项目真正"可玩"。

### 10.1 设计原则

- **不破坏项目核心**：默认**关闭**。关闭时 `sim.thrust` 恒为 0，物理
  积分器中那一行 `pr.vel += this.thrust * h` 相当于不存在，行为与
  之前完全一致。打开推进器才主动注入加速度。
- **玩家输入视为"力"，与引力并列**：与系统内其他天体的引力、介质
  阻尼一样被并入加速度，每物理子步（h = dt/subSteps）叠加到 `pr.vel`。
  关闭后受速度上限 `PROBE_MAX_SPEED = 34` 截断，与引力加速有界同一逻辑。
- **方向基于摄像机视角**：`forward = target - camera.position`（与
  OrbitControls 实际看向的方向一致），WASD 推力始终在玩家"眼里"的
  前/后/左/右——符合第三人称驾驶的肌肉记忆。自由视角时能"看到哪儿
  就推哪儿"，跟拍时镜头固定方位但推力仍能选方向。

### 10.2 键位（main.js 集中维护）

- `W` / `↑` — 沿摄像机前向推进
- `S` / `↓` — 后退
- `A` / `←` — 左移
- `D` / `→` — 右移
- `Q` / `Space` — 上移
- `E` / `Shift` — 下移

WASD 与 QE 分列键盘左右两半，沿用 FPS/太空飞行游戏的标准键位；
Space/Shift 作为备选避免"手指离开 WASD 也要用上"。

### 10.3 物理与积分

`sim.config.thrustEnabled: false`（默认） / `sim.config.thrustMag: 8`
（加速度大小，与引力 G=16 同量级——足以改变航向、抵近系统或主动
逃逸引力井，但不会"超人化"甩开物理节奏）。

`sim.thrust = [x, y, z]` 是世界坐标推力向量，每帧由 main.js 在物理
子步循环**之前**按"键位 × 摄像机方向 × thrustMag"重算并写入。
物理积分器在介质阻尼之后、速度上限之前应用：

```js
if (this.config.thrustEnabled) {
  pr.vel[0] += this.thrust[0] * h;
  pr.vel[1] += this.thrust[1] * h;
  pr.vel[2] += this.thrust[2] * h;
}
```

推力**不被介质阻尼吃掉**（顺序上在 IGM_DRAG 之后），玩家能"对抗"
系统阻尼与引力井——这是引擎推力的物理直觉。

### 10.4 引擎尾焰（cosmos.js render）

推进器开启且有实际键位输入时显示，关闭或无输入时立刻隐藏。

- 几何：`ConeGeometry(0.7, 1.0, 24, 1)`，底端（粗端）从 +Y/2 平移到
  原点，模型坐标系下底端 = (0,0,0)、顶端 = (0,1,0)
- 朝向：`quaternion.setFromUnitVectors(Y, -velDir)`——模型 +Y 朝速度
  反方向（"喷气往后喷"），用 `probeTrail.position` 同步到 probe.pos
- 长度：`0.8 + speed * 0.22 + thrustMag * 0.05`，clamp 到 6.0——速度
  越快尾焰越长（视觉"加速感"）
- Shader：Additive 混合，alpha 沿长度方向 `pow(1 - t, 1.4) * 0.95` 衰减；
  颜色从近端白热 (1.0, 0.95, 0.88) 到远端青蓝 (0x7ab8ff)，模拟真实
  喷气的温度梯度。配合 `threshold = 0.30` 的 UnrealBloom 强化出
  "光带"质感
- 不与小球 mesh 父子绑定（避免被死亡演出的 `scale/quaternion` 污染），
  每帧自己同步位置

### 10.5 UI 控件（index.html）

- 顶栏按钮 `🚀 推进器：开/关`（与 `🎥 轨迹跟拍` 并列）
- 折叠组 "推进器（实时可调）" — 推力大小滑杆 0~30，默认 8

推力大小滑杆位于"引力实验"之前，作为独立的折叠组（与重力 G 同为
"实时物理调节量"但语义独立），避免把游戏操控与天体物理混在一起
造成认知干扰。
